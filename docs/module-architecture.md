# 子项目架构：LLM 材料生成、课程编译与课堂播放

按用户确认的预期，流水线是 **LLM 生成文稿材料 → `content-generator` 编译 → `lesson-player` 播放编译产物**。LLM 负责创作材料，`content-generator` 的名字表示生成可播放课程资源，不表示它负责 AI 写文稿；`lesson-player` 只执行编译后的语音、板书和动画数据。

同一仓库内用 npm workspaces 管理材料生成、编译、播放三个独立业务模块及共享协议模块。上游 `lesson-draft-generator` 已增加多模型协议适配和人工材料导入；未拆远程仓库或发布 npm 包。真实供应商账号与教学质量尚未验收。

```text
lesson-draft-generator（Node.js，材料创作，上游）
  LessonBrief → 多模型 Provider → 校验 / 显式修复
  人工材料 → 同协议校验，不请求模型
  → 文稿、板书要点、动画指令与语义锚点
                 │
                 ▼
LessonDraft 0.1.0（已实现，统一材料协议）
                 │
                 ▼
content-generator（Node.js，课程资源编译）
  材料校验 → TTS → 真实词时间戳 → 语义锚点 → 课程事件编译
                 │
                 ▼
编译产物：LessonSpec 0.1.0 + 固定音频 + VTT 字幕
          （LessonSpec 由 lesson-schema 定义）
                 │
                 ▼
lesson-player（React，下游）
  同一音频时钟 → 语音＋板书＋动画
  播放 / 暂停 / seek / 倍速 / 重播 / 画面恢复
                 │
                 ▼
app + examples（集成演示，不属于三个业务模块的核心）
```

## 统一能力扩展

宿主 `capabilities/index.ts` 注册能力包，向三个独立模块注入同一份纯数据规则、备课说明和时间字段，向浏览器注入对应绘制入口。模块仍只依赖共享协议，不导入宿主或彼此。现有默认能力兼容保留，新增 `scene` 在自己的目录内实现；后续增加表现能力采用“新增目录＋注册一项”。完整接口与边界见[能力包规范](./capability-packs.md)。

## 项目边界

| 子项目                            | 输入与输出                                                             | 不负责                                                    |
| --------------------------------- | ---------------------------------------------------------------------- | --------------------------------------------------------- |
| `packages/lesson-draft-generator` | 备课需求／人工材料 → 校验后的 `LessonDraft` 与生成报告                 | TTS、音频、文件托管、React、动画渲染、知识正确性保证      |
| `packages/lesson-player`          | 已编译 `LessonSpec`、媒体地址 → 同步课堂组件与控制接口                 | 生成讲稿、调用 TTS、读密钥、猜测事件时间                  |
| `packages/content-generator`      | `LessonDraft` 与编译配置 → 课程 JSON、连续 MP3、字幕、实测报告         | AI 创作文稿、React 页面、动画渲染、播放时钟、实时播放控制 |
| `packages/lesson-schema`          | 材料／产物纯数据协议、运行时校验、共用动画状态规则；供三个业务模块依赖 | Provider、播放器组件、教学策略                            |

三个业务项目互不依赖，只依赖共享协议。播放器把板书、字体资源、默认动画语法和控件收在自己的目录，样式也可单独导入，不依赖 `app/`、`components/`、`lib/` 或演示应用的 Tailwind 配置。中文原字形和笔画资源保持不变；宿主可继续提供原来的 `--font-hand` 字体变量。

上游 LLM 可替换，也可由人工材料替代。编译器不依赖材料由哪个模型生成；播放器既不依赖 LLM，也不依赖编译器的运行环境。TTS、音频制作、字幕和时间轴对齐属于编译阶段，不迁入播放器。

内容模块可以在没有 React、浏览器或 API Key 的情况下构建；播放预先生成的课程也不需要生成模块或 API Key。动画 grammar 的代码由开发者注册，生成结果只能引用已支持的 grammar ID，不能生成并执行组件代码。

## 文稿材料与编译产物的区别

文稿材料表达“讲什么、画什么、在哪句话配合哪个动作”，不要求 LLM 预先猜测最终音频的秒数。编译产物表达“在实测音频的第几秒执行哪些明确事件”，供播放器直接重建画面。

已定义结构化 `LessonDraft 0.1.0` 输入，包含章节／旁白片段、板书内容、受支持的动画配置与动作，以及动作绑定的语义短语。纯长文可以作为备课原料，但缺少板书和动画安排时不能直接按规则编译成完整课堂，应先在上游补全材料。

例如，材料写“讲到‘变成水蒸气’时写出‘蒸发：液态水 → 水蒸气’，并激活蒸发节点”。编译器合成旁白后，用真实词时间戳确定该短语的出现时刻，再输出 `board.write` 和 `visual` 事件；播放器只读取这些事件，不再次理解文稿或调用模型。

动画材料只能引用支持的 grammar、节点／连线和动作，不能携带生成的 React 组件或脚本。语义锚点缺失／不唯一且未指定出现次数、动作不受支持或时间戳不匹配时明确失败，不通过字符数估算或生成代码掩盖缺失。

`LessonDraft` 已有公开类型和输入校验；`compileLessonDraft()` 是完整公开编译入口。字段、真实词边界定位、缓存模式和输出资源见[统一材料与编译](./lesson-draft.md)。

- 旧 `lib/tts/`、`lib/lesson.ts`、`lib/handwriting.ts`、`packages/board-renderer/` 和 `packages/visual-grammars/` 仅保留兼容转出口，避免打断旧调用；新代码使用命名包入口。

## 各自开发与构建

在仓库根目录先安装依赖：

```bash
npm install
npm run build -w @learn-anything/lesson-schema

# 只构建上游材料生成项目，不调用模型
npm run build -w @learn-anything/lesson-draft-generator

# 只构建课堂播放项目，不启动或构建演示网站
npm run build -w @learn-anything/lesson-player

# 只构建课程编译项目，不生成付费音频
npm run build -w @learn-anything/content-generator
```

也可以在各子项目目录运行 `npm run build`，前提是共享协议已经构建。各自拥有自己的 package.json、类型检查和构建配置，不继承应用路径别名或框架配置。依赖安装目前由工作区统一管理；不是已发布的独立仓库。

全量构建与检查：

```bash
npm run build:modules
npm run typecheck:modules
npm test
npm run test:modules
npm run lint
npm run typecheck
VINEXT_NO_DEV_LOCK=1 npm run test:browser
npm run build
```

`npm run build` 先构建模块，再构建集成演示。`npm run test:modules` 验证生产包在仓库外的临时 React 应用中可被消费；不调用 TTS，不发布或部署。

## 使用播放项目

```tsx
'use client';
import {
  ClassroomPlayer,
  type LessonSpec,
} from '@learn-anything/lesson-player';
import '@learn-anything/lesson-player/styles.css';

export function Classroom({ lesson }: { lesson: LessonSpec }) {
  return <ClassroomPlayer lesson={lesson} />;
}
```

支持公开子入口 `./clock`、`./runtime`、`./board`、`./grammars`。默认入口为构建后的 ESM 和类型声明；开发工作区通过显式 `learn-anything-source` 条件使用源码。该条件只供源码工作区选择，仓库外普通开发模式仍加载生产包中的 ESM，不引用未打包的源码。普通 React 宿主只需要组件、CSS、共享协议和媒体文件，不需要本应用的页面框架。

缺少中文笔画数据的字符仍采用手写字体逐字渐显。没有完整中文字形路径库，不因项目拆分而扩大这一能力承诺；仓库外宿主若需要相同的后备字形，应提供相同的 `--font-hand` 字体。

## 使用编译项目的现有产物接口

```ts
import { createLessonArtifacts } from '@learn-anything/content-generator';

// compiledLesson 已按实际音频的语义锚点编译。
const { lessonJson, captionsVtt, resources } =
  createLessonArtifacts(compiledLesson);
// 调用者负责保存 JSON / VTT，并将音频放到 resources.audio 对应的位置。
```

注意：`createLessonArtifacts()` 的输入已经是编译后的 `LessonSpec`，它做产物校验和序列化，并不是“文稿材料 → 课程”的通用编译入口。新材料使用 `compileLessonDraft()` 完整入口，或已有实测片段时的 `compileAlignedLessonDraft()`。

资源必须是固定的、可被宿主读取的本地或 HTTPS 地址，课程中的 duration 必须匹配实测音频。播放器继续严格检查实际音频时长，不会因为上游变成另一个项目而改为估算同步。
